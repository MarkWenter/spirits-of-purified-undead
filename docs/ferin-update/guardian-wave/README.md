# 秽鬼之守护 · 挥剑剑气

### ferin.26 中途开始观察

服务器在客户端开始追踪剑气时附带一次 25 字节的发射信息，记录最初的坐标与用手。即使射手随后换手或已离开观察范围，客户端也能按已飞距离继续播放五种武器的光迹和旋转。旧服务端缺少这段信息时沿用本地估算。服务端仍按原来的路径、距离和逐目标去重规则判定命中。

两版开发客户端通过 `GUARDIAN_WAVE_PAIRING_OK` 和 `GUARDIAN_CLIENT_OK`。回归覆盖空发射数据、无效坐标、中途加入视野和本地预显示后延迟收到服务端确认，确认后只显示一次剑气。

五种武器的网格在资源重载时完整校验。同一把费林剑的女仆虚影和挥剑幻影共用读取规则。实机用不完整的高优先级格洛特模型检验回退，恢复了内置战锤的 312 个四边面。

### ferin.24 出手位置与抽取

武器幻影和光迹一起从握剑侧飞出。相对原剑气起点，视觉起点向握剑侧移 0.36 格、向视野下方移 0.16 格。偏移随实际飞行距离线性收小，15 格处汇入原命中线，总偏角约 1.5°。玩家选择左主手时水平镜像。视觉位置按发射时的朝向计算，飞行期间转身不会牵动已发出的武器。

两版成品均在开发世界核对了第一与第三人称左右手、旁观发射和本地挥剑确认。第一人称距离起点 1 格时，幻影中心与原命中线水平相距 0.336 格，到第 14 格时缩至 0.024 格。专用服务器回归覆盖了墙体截断、逐刻命中和原有射程。[左右手出手实拍](hand-launch.jpg)

五种外观使用相同权重，每次挥剑各占 20%，同一把武器可以连出。本地预测和其他客户端使用同一组发射者、挥剑编号进行有界随机抽取，单独由服务器发起的挥剑使用同步的实体编号。

为复核格洛特战锤的出现率，用两个版本各自的选择算法，分别对四个发射者编号（1、31、319、1001）各取连续 250,000 次。下表为 100 万次样本中的实计次数。

四个新工程均内嵌 64×64 贴图。费林的剑直接引用既有的网格与图集。剑气实体的渲染入口为 `GuardianWaveRenderer`，一次只绘制选中的武器。客户端用已同步的持有者 ID 和挥剑编号等权选取外观，本地预测和旁观客户端据此取得相同结果。没有预测编号的服务端攻击使用已同步的实体 ID。模型沿用原来剑气的俯仰、朝向和随机倾角。

`textures/effect/guardian_wave/surface_light.png` 的五个图块对应武器受光部位的 UV。`wakes.png` 每行属于一种武器，包含八个演变阶段。旋转武器的拖影按刃口或锤面在较早时刻的位置生成。直进武器的尾迹以球面、锤箍或枪锋为起点，随剑气实体一起消失。费林协同攻击由自己的渲染入口负责。[费林协同攻击记录](../DYNAMIC_SLASH.md)

两版分别用成品 JAR 进入开发世界，进行资源重载、本地挥剑预测、服务器确认与旁观视角测试。五种形态各抽取两种原有倾角拍摄。专用服务器检查了原有飞行距离、逐刻位移、伤害、墙体截断和重复包处理。与 ferin.22 的两个成品逐文件比较，旧游戏类中只有 `GuardianWaveRenderer.class` 发生改变。[ferin.22 的剑气渲染实现](https://github.com/MarkWenter/spirits-of-purified-undead/blob/d331072be7076eb5ba88b4fadf4b0b0dc2db4703/src/main/java/dev/purifiedundead/client/GuardianWaveRenderer.java)
