# 0.44.0 验证记录

验证环境为工程开发实例；未使用正式存档。

最终结果：Forge 122 项、NeoForge 124 项既有单元测试通过；两版新增方块服务端检查、完整既有服务端回归与最终客户端画面检查通过。两版分别有 100 个白巫女手记相关资源与 0.43.2 逐字节一致，生产包均未包含测试类。

## 服务端

两版新增 `FoundryServerSmoke`，接入现有开发服务端回归入口。检查：

- 北、东、南、西四种朝向下，原版漏斗从顶部、左侧、右侧分别向正确槽位转移物品。
- 正面、背面及底部拒绝输入；下方原版漏斗仅取成品，不取原料或燃料。
- 四槽库存序列化与重新加载；成品槽拒绝手动放入；Shift 从机器转入背包。
- 服务端 50% 进度、界面数据和亮起状态；归零后恢复待机。
- 拆除时库存数量守恒，不重复掉落。
- 原石、深板岩原石与混合配方均成立，错误剑被拒绝，产出正确。

Forge 首轮真实漏斗检查发现基础容器提供的不分面物品 capability 会绕过底部限制，已增加 `SidedInvWrapper` 并管理其失效/恢复生命周期，修复后通过。NeoForge 的原版漏斗通过 `WorldlyContainer` 分面转移。

两版均要求日志出现 `FOUNDRY_SERVER_OK`，同时继续核对原有净化、遗物、手记、进度、极限保命、费林生命周期及项目审查通过标记，无 `_FAILED`。

## 客户端

使用独立开发存档 `diary-validation` 和 `FoundryClientSmoke`，由集成服务端放置方块并打开真实菜单。验证两种方块模型加载、0/50/100% 进度同步，并截取界面与待机/亮起方块画面。必须出现 `FOUNDRY_CLIENT_OK`，不能以标题页启动代替检查。

首轮 NeoForge 客户端测试角色在高空下落导致距离超限自动关闭菜单，已为测试角色启用创造飞行，未放宽生产代码的距离校验。最终手臂定位及最近邻整理后的资源重新进行客户端验证。

## 范围

本阶段没有实际加工配方，进度和亮起由开发测试单独驱动，不代表已有生产规则。未验证其他模组管道或大型多人服组合。测试代码仅位于 smoke 源集，不进入生产 JAR；白巫女手记资源应与 0.43.2 保持逐字节一致。

安装包校验值、测试计数、运行日志与截图保存在两版交付目录的 `验证记录/0.44.0/`。
