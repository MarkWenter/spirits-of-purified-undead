# 石板更新验证记录

## 0.45.0 第二部分验证

两版均在工程开发实例完成构建与既有单元测试（Forge 122 项、NeoForge 124 项），并运行独立服务端完整回归和实际客户端验证。以日志中的通过标记为准，不把 Gradle 成功退出当作游戏逻辑通过。

新增服务端检查覆盖：12 条默认铸造配方的批量输入／产出／燃料计数；64 煤炭产出容量限制、内部余料保存与下一批继续；保留战士模板；四朝向漏斗输入、只提取成品、拆除守恒；合成追忆返还石板；手记拒绝其他物品与重复追忆、锁定主手、即时存储、手持无效与佩戴生效；满背包待发与费林一次性奖励；守护宝具生命值、全局遗物倍率和卸下撤销；姐妹等级／时长／冷却；疾跑与速度药水档位；下劈及击杀下劈溅射；群体眩晕；四种异常、火焰免疫、夜视、游泳、抢夺；挂墙重力与释放；包含玩家开箱上下文的跨模组宝箱路径、主世界／下界／末地限制和 1—5 数量。

异常状态测试暂时将概率设为 100% 核对四种状态，随后恢复默认 25%；伤害计数测试将测试玩家的 Apothic 随机暴击率归零，避免随机暴击改变预期数字。测试结束不改变发布默认配置。

客户端检查实际加工周期、服务端进度同步、64 个成品、待机／亮起外观、19 件物品模型、主手使用打开手记、八个追忆槽同步。额外用真实客户端玩家贴墙按住跳跃，验证停止下落及松手后继续下落。通过标记为 `FOUNDRY_CLIENT_OK`、`SLATE_CLIENT_OK`；服务端为 `SLATE_SERVER_OK`、`FOUNDRY_SERVER_OK` 及原有净化／遗物／手记／进度／极限保命／费林生命周期／项目审查标记。

此轮修正了手记槽位索引遮蔽造成的主手锁定失效、开箱上下文带玩家时被误排除、NeoForge 致命命中后的溅射过滤，并为挂墙加入临时重力属性修正。集成检查延后到强制加载的开发区块就绪后执行，避免把尚未进入实体查询范围的掉落误判为丢失。

新增物品贴图均为 16×16，两版对应资源一致；与各自 0.44.2 产物比对，100 个白巫女手记相关资源不变，旧翻译键值不变，生产 JAR 不含验证类。此轮没有安装任意第三方遗迹模组逐个试玩；兼容范围以第二部分说明为准。

最终日志、截图、结果和安装包 SHA-256 位于两版交付目录的 `验证记录/0.45.0/`。

## 服务端

两版新增 `FoundryServerSmoke`，接入现有开发服务端回归入口。检查：

- 北、东、南、西四种朝向下，原版漏斗从顶部、左侧、右侧分别向正确槽位转移物品。
- 正面、背面及底部拒绝输入；下方原版漏斗仅取成品，不取原料或燃料。
- 四槽库存序列化与重新加载；成品槽拒绝手动放入；Shift 从机器转入背包。
- 服务端 50% 进度、界面数据和亮起状态；归零后恢复待机。
- 拆除时库存数量守恒，不重复掉落。
- 原石、深板岩原石与混合配方均成立，错误剑被拒绝，产出正确。

Forge 首轮真实漏斗检查发现基础容器提供的不分面物品 capability 会绕过底部限制，已增加 `SidedInvWrapper` 并管理其失效/恢复生命周期，修复后通过。NeoForge 的原版漏斗通过 `WorldlyContainer` 分面转移。

两版均要求日志出现 `FOUNDRY_SERVER_OK`，同时继续核对原有净化、遗物、手记、进度、极限保命、费林生命周期及项目审查通过标记，无 `_FAILED`。
