# 0.47.0 兼容性审查

## 审查范围与修复

检查两版石板物品、手记容器与追忆效果、铸造处理、配方同步、JEI 生命周期、可选反射桥、战斗状态集合、客户端光球与网络入口。未向其他模组的菜单注入代码，也未使用吞掉所有异常的全局包装。

已修复：重复反序列化物品、已完成奖励的重复扫描、铸造无效扫描和进度脏标记、JEI 同配方重复注册、过期手记菜单访问、配置和同步输入缺少边界、可选桥的运行时接口异常。

配置上限为 8 MiB、4096 条配方、同步估算不超过 900000 字节；物品 ID 上限 256 字符。既有正常配方无需修改。异常配置不会覆盖原文件或清空机器。Forge 非正常追忆 NBT 列表超过 256 项时效果查询返回空，保留原数据。

检查到既有战斗状态集合具有退出/停服清理；光球可见数、动态光源数、刷新频率已有限制。保留抢夺重算的重入保护。没有足够证据时未改动这些玩法逻辑。

## 验证方法

在开发实例运行两版单元测试、实际独立服务端和客户端，核对游戏内通过标记。覆盖旧玩法、铸造余料与漏斗、手记/追忆、死亡与跨维度、锻造与酿造、可选亡灵名单；新增 4096 配方索引、十万空闲加工调用、异常同步数据、手记即时修改及过期菜单测试。JEI 测试包含正常配方来源和 80 次配方切换。

2000 次追忆查询的线程分配测量：Forge 新路径 32000 字节、原完整读取路径 5496232 字节；NeoForge 新路径 176000 字节、原路径 2000000 字节。此为局部开发环境测量，不能换算为整合包帧率提升或整机死机修复率。

## 验证边界

完整第三方整合包及长时间多人压力尚未验证。本次开发客户端曾出现原生进程异常退出（Windows 堆损坏），单独保留失败日志与复测结果，不将 Gradle 退出码当作玩法通过依据。仅凭这种记录不能归因到特定模组、驱动或硬件。详细实例诊断保留本地，不公开玩家原始日志与启动参数。

## 本轮通过结果

Forge 47.3.22 / Java 17：122 项单元测试通过；NeoForge 21.1.248 / Java 21：124 项通过。两版独立服务端全部回归标记通过；真实客户端 FOUNDRY_CLIENT_OK、SLATE_CLIENT_OK 通过。Forge JEI 15.20.0.116 复测、NeoForge JEI 19.57.0.450 均通过 JEI_COMPATIBILITY_OK、JEI_SOURCE_AUDIT_OK、LILY_JEI_OK、SLATE_JEI_OK。每版 80 次刷新仍只有 13 个配方对象及可见配方。

打包检查：各 251 个既有美术资源完全不变、101 个可选亡灵标签保持可缺省，发布 JAR 不含测试类。首次 Forge JEI 原生失败记录保留于本地验证目录。
