# 污秽之雨第一部分 · 实施依据

状态：**第一部分已实现。** 本文件保留实施设计；最终行为与验证见 [实现记录](PART_1.md)，已纳入用户最后补充。适用主模组 Forge 1.20.1 / 47.3.22 与 NeoForge 1.21.1 / 21.1.248 两个实际工程。以用户本次要求优先；本文件中的实现建议不等于已完成代码或验证。

## 1. 范围与天气

主世界天气默认限定为雨天或雷阵雨，不出现晴天。污秽事件是独立于普通雨/雷暴的共享环境状态，由服务端按世界判定，不按玩家分别抽取。下界、末地及其他维度不触发污秽之雨。多人看到同一事件。

按原版当前位置降水类型处理：RAIN 为污秽之雨，SNOW 为污秽之雪，NONE 不改变。不能用温度阈值简单替代实际降水类型，也不能把原版 isRainingAt 直接用于雪。暴露判定复用原版天空、MOTION_BLOCKING 高度和实体身体位置/顶部的语义。屋檐、建筑、洞穴可以避开；普通浸水不算暴露，实际水面以下的生物不受伤。

未来世界创建选项、配置、指令和解除仪式经同一天气策略入口接入，具体内容统一后续制作。天气限制和污秽事件启用状态分别保存，避免未来解除功能与实体效果耦合。

## 2. 概率、前兆、持续时间与冷却

- 符合触发条件时每秒一次，概率 0.1%（0.001），主世界只判断一次，与在线人数无关。
- 概率命中后立即进入 **15 秒 / 300 游戏刻**前兆，提示：**污秽之雨即将降下……**
- 前兆期间村民避险，客户端外观逐渐改变；污秽效果、伤害、转化进度尚不生效。前兆期间不再抽取概率。
- 前兆结束进入正式事件，随机持续 **5—10 分钟 / 6000—12000 游戏刻**。持续时间不包含前兆。
- 预警、落雨期间不抽取概率；落雨期间为无计时冷却，正式事件结束才开始 **15 分钟 / 18000 游戏刻**有计时冷却。冷却不积攒补偿概率。
- 正式事件结束立即停止新的暴露结算，无结束缓冲，并提示：**污秽之雨暂时停下了……**。之后仍为普通雨或雷阵雨。
- 使用游戏时间，不使用昼夜时间，睡眠和 /time set 不跳过计时；服务器关闭/游戏暂停不消耗游戏时间。

数学评估：有效等待的期望为 1000 秒（16 分 40 秒），包括平均落雨时间、预警和结束后十五分钟冷却的两次触发平均间隔约 2365 秒（39 分 25 秒）。冷却结束后等待 5/10/15 分钟，至少命中一次的概率约 25.9%/45.1%/59.4%。这些是统计值，不是固定周期或保证上限。

实现建议：只在至少有玩家处于主世界时抽取新事件，已触发事件与冷却仍按世界游戏时间推进；主世界无玩家时不影响其他维度玩家。该空世界触发策略是实现建议，用户尚未单独指定。登录/换维度时同步当前阶段和剩余时间，不能向新加入者伪造一次新的全服触发。

## 3. 玩家效果与一次性极限保命

露天玩家持续刷新 **急迫 I、力量 I、秽鬼化，各 10 秒 / 200 游戏刻**。建议每秒刷新一次，保留已有更强或更长的同类效果。离开遮挡判定范围/主世界或事件结束后停止刷新，雨赋予的效果自然到期；不能删掉玩家其他来源的同类效果。

秽鬼化复用 ModEffects 的现有身份，普通模式在秽鬼化下死亡/重生仍经既有契约获取和奖励补发链。契约只发一次，满背包 pending 保留。

用户明确：极限模式只有一次秽鬼化免死并取得契约的机会，所有来源共用，不因重新淋雨/喝灵药/重登恢复。

准备阶段核对（本次已修复）：两版 HardcoreBlightRescue.onSaved 当时未检查已获取契约或保命已使用，只保证奖励服务去重；现有实现可能重新取得秽鬼化后再次保命。本次已补齐一次性保护，而非假定已经成立。保命成功即消费并保存资格，不能等奖励实际进入背包；与死亡换体/重登保存链一致。旧存档已经有契约获取记录的玩家不能因升级重新得到机会。真实图腾和其他遗物的独立保命仍保留。

## 4. 生物伤害、免疫与玩家归属

用受影响实体类型标签覆盖广泛的原版生物，范围不再仅为被动动物；不包括玩家的魔法扣血处理，玩家走上述效果链。通过明确例外/免疫名单控制范围，其他模组可扩充标签。

被实际污秽降水暴露的适用生物每 25 刻经正常魔法伤害流程扣 1 点生命，中毒 I 速率但可致死；玩家无此伤害。保持其他模组的伤害/死亡事件以及正常抗性语义。不能直接改生命值，也不能伪装成玩家伤害。

未暴露而在水中的鱼等生物不受伤；不能因为生物接触到浅水就一概免疫，也不能按鱼类身份永久免疫真正露出水面的个体。

玩家驯服或明确属于玩家的生物不受任何污秽降水伤害。优先读取原版归属接口和玩家 UUID，不以主人当前在线/在同维度为条件。狼、猫、已驯服坐骑等由标准关系覆盖；狐狸按信任玩家关系做专门适配。车万女仆的 1.20/1.21 源码均继承 TamableAnimal，可优先走标准归属接口。第三方自定义 NBT/能力/附件需要专属、缓存的适配，不能扫描任意 NBT 字段猜测主人或每刻完整序列化实体。

保留类型免疫名单配置入口、实例归属适配入口。配置文件与其余管理选项统一后续制作，不在本阶段临时扩张管理界面。保护是否同时禁止未来其他转化作为实现建议记录：建议归属/免疫筛选先于转化，防止玩家虽不掉血却失去所属生物；用户未单独指定全部未来转化规则。

**尚未给出数值：** 生物伤害量与扣血间隔。实施前需确定，不能把历史评估中的示例当作用户确认数值。

## 5. 掉落抑制与玩家伤害记录

用户规则：**被污秽降水致死且从未受到过玩家伤害的生物，不掉落物品。** 曾受玩家伤害的生物保留正常掉落规则，不额外增加奖励。

以最终致死来源为准，仅污秽降水伤害执行抑制；先被雨伤过、随后被玩家或其他原因杀死，不因曾淋雨而被取消掉落。普通魔法伤害不能被误识别为污秽降水。

“曾受玩家伤害”按实体生命历程记录，不只读取原版最近受玩家伤害的短期计时。记录实际成功的玩家伤害及可明确归属于玩家的攻击来源，包括玩家射出的投射物、已有协同攻击；取消/未造成有效伤害的攻击不能标记。具体伤害事件需要分别核对两版结算与吸收语义。玩家所属生物攻击的归因按已有正常击杀归属规则评估，不因雨伤害自行伪造玩家来源。

记录须在实体保存/重载时保留，并在本模组实体转化时转移。已有旧存档无法恢复过去已经失去的玩家攻击历史，不能声称能够追溯。

两版优先使用 LivingDropsEvent 的取消入口抑制标准物品掉落，包括标准装备掉落链，不扫描并删除附近所有 ItemEntity。仅物品掉落按用户本次要求处理；经验与玩家击杀成就/战士奖励不擅自改变。保留正常掉落不等于强行把雨的致死归属改给玩家。

## 6. 村民避险

概率命中时（前兆开始）让适用区域内已加载的村民开始避险，正式事件期间持续维持。参考原版 Brain 中 HOME/HIDING_PLACE/WALK_TARGET 和躲藏行为，加入模块专属条件；避免伪造袭击状态、生成袭击或传送村民。

原版躲藏行为有独立超时与日程恢复，不能一次启用后便认为可以覆盖完整事件。避难目标必须实际遮挡降水；低频、有限范围寻路，不每刻全村扫描。已有屋内村民不反复寻路；不破坏村民其他关键行为或 NoAI。没有可达遮挡处的村民仍可能受到伤害。事件结束后释放本模块的避险状态，恢复原日程。

## 7. 铁傀儡与唤魔者转化

保留怨念污秽点击转化途径，增加环境转化：普通铁傀儡→现有污秽傀儡，普通唤魔者→现有污秽国王。已经转化的实体不再转换。

暴露进度使用用户新规则：

- 正式污秽事件中，每暴露 1 游戏刻，进度 **+1**。
- 每个没有增加进度的实际游戏刻，进度 **-1**，最低 0。
- 达到 **100** 刻立即尝试转化，不再使用“离开遮挡就立即清零”的旧建议。
- 此规则需要逐刻检查，但只对这两类候选以及有残余进度的候选工作。事件不活跃且进度为 0 时快速返回；衰减阶段无需天空/群系查询。
- 不强制加载实体/区块；卸载期间不能积累暴露，建议下次加载用已保存时间差补算衰减，避免把久远残余当作新的连续暴露。

抽出小型共享转化服务，点击与降水分别校验各自前置条件，共用实体创建/状态保留/成功加入后移除原实体的核心。保留位置、名称、生命比例及各自必要数据，并转移玩家伤害记录。环境转化不要求附近玩家持有契约，也不消耗玩家物品。

先确认转化是否成功再移除原实体；创建/加入失败保留原实体，重试频率受限。固定转化与本刻伤害的先后顺序，避免达到阈值时先被雨伤害杀死。不要因被雨转化就授予战士奖励，原有玩家击杀与契约条件继续有效。

性能评估：两种转化方案均需要逐刻判定暴露，才能发现两次低频检查之间的遮挡变化。累积/衰减只比立即清零多了一个有界整数运算，性能处于同一量级。开销主要来自暴露查询、目标数量和第三方归属适配，而非加减。只处理已加载候选、早期筛选、不全世界扫描、不每刻实体整体 NBT 序列化，不会引入新的大范围扫描。

## 8. 客户端表现、两版接入与验证

污秽雨丝为灰色夹少量红色，污秽雪花采用相应表现；前兆 15 秒内逐渐改变，正式事件结束即停止特殊天气状态，无结束缓冲。普通降水与无降水区域保留原有表现。雨/雪主体纹理与落地粒子分别处理，保留原版遮挡、密度和光照逻辑。

可增加云色、天空/雾色和上述明确提示作为替代表现；部分光影也接管云与天空，不能承诺变色云覆盖所有光影。服务端效果独立于视觉路径；实际测试原版及所选光影，未验证的组合不称为已兼容。

两版事件适配：Forge 使用服务端 TickEvent.LevelTickEvent、LivingEvent.LivingTickEvent、对应 PlayerEvent/LivingDropsEvent；NeoForge 使用 LevelTickEvent.Pre/Post、EntityTickEvent.Post 筛选 LivingEntity、对应 PlayerEvent/LivingDropsEvent。事件处理做筛选和委派，规则/存储/效果/转化职责留在明确服务中。实体写入与伤害全部在服务端主线程。

世界阶段、时限与冷却经 SavedData 保存；客户端只接受服务端状态同步，在登录/换维度/重连时补齐并在退出时清理。逐刻进度只是内存中的小整数更新，不每刻写磁盘。专属伤害类型与两版相应 JSON 目录分别处理；所有新增 Mixin 继续使用项目可串联规范，并验证实际正式加载器启动。

验证至少覆盖两版概率/冷却边界、15 秒预告与提示、雨雪/NONE、遮挡与浸水、多人共享、保存/重载与换维度、一次性极限保命、主人离线和狐狸/女仆归属、村民寻路、累积/衰减（含 99/100 边界）、转化失败保护/状态转移、致死来源和曾受玩家伤害的掉落差异，以及普通雨/雪/光影表现。开发探针与测试不进入成品。
