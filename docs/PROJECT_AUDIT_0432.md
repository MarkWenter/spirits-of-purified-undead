# 0.43.2 项目检查与回归记录

检查对象：Minecraft 1.20.1 Forge 与 1.21.1 NeoForge；基线为 0.43.1。检查、测试均在工程开发环境进行，不操作玩家正式游戏实例或正式存档。

## 检查范围

| 范围 | 检查重点 |
| --- | --- |
| 注册与加载 | 两版入口、必需依赖、事件注册、客户端与服务端分离、NeoForge Mixin |
| 战斗 | 菲琳连击、暴击与吸血、乌尔夫追击、魔法球、标记、诅咒与减伤的事件顺序、伤害吸收、队友与宠物过滤 |
| 成长与保存 | 契约与战士的一次性发放、待领取奖励、死亡保留、重生复制、升级、极限保命 |
| 饰品与净化内容 | 属性增减、保命冷却、莉莉手记记录、锻造、初次赠书、纯净灵药与装备 |
| 进度与资源 | 旧存档补发、配方、掉落、标签、模型贴图与音效引用、中英文本键、JSON 格式 |
| 兼容与维护 | 可选联动的反射入口、缓存清理、网络请求由服务端判断、版本 API 差异及重复逻辑 |

静态资源检查覆盖 Forge 的 136 个主源码文件清单与 216 个 JSON、NeoForge 的 137 个主源码文件清单与 243 个 JSON。Java 检查重点为上述功能入口与调用链，文件清单数量不代表每行代码均获形式化验证。所有 JSON 均可解析，无重复键；本模组显式模型纹理、父模型与音效引用无缺失；中英文语言键一致。

## 已确认并修复

1. **死亡界面期间丢失保留饰品（两版）**：保留缓存的定时恢复不检查玩家是否存活，会在重生前将缓存清空并填入旧玩家背包，而普通重生不会复制该背包。修复为存活后才恢复。服务端测试覆盖死者不发放、缓存保留、重生一次性恢复。
2. **死亡界面期间丢失待领取奖励（两版）**：背包因死亡腾空后，奖励定时补发向死者背包插入并清除 pending 标记。修复为物品插入必须面向存活角色；已承诺的奖励仍保留待领取标记。极限保命流程先恢复生命再发放，避免改变 0.43.1 的即时奖励行为。
3. **菲琳旧攻击跨角色生命周期残留（两版）**：原连击保存/复制保留 stage 和攻击位置，换维度后还可能在新世界沿用旧坐标。重生、换维度，以及角色死亡、旁观或失去契约后取消活动连击和排队输入；保留召唤冷却，避免重生刷冷却。正常连击的伤害、时序、动画与离线保存规则不改动。
4. **溢出伤害导致过量吸血（仅 NeoForge）**：原移植在 LivingDamageEvent.Post 中通过“剩余生命＋伤害”倒推受击前生命，致死时生命被截到零，倒推失真。已移到 Pre 的最终减伤阶段，以受击前生命为上限并扣除伤害吸收，遵循 Forge 的现有规则。实测基线：目标剩 2 生命、攻击者 10 生命，高伤害击杀后错误恢复至 20；修复后为 10.4。另测伤害全部被黄心吸收时不吸血。

## 回归与保持范围

- 原有单元测试继续执行，并新增连击取消时冷却持久化、排队输入与命中缓存清理的测试。
- 服务端执行净化第一/二部分、莉莉手记、旧档进度补发、极限保命、菲琳大体型/多部件目标，以及本次死亡与吸血回归。
- 补充遗物配方/掉落/属性/保命/摔落伤害与白巫女手记配方检查。
- 客户端执行资源加载及进度图标、秽鬼化图标检查。
- 保持配方、数值配置、贴图、音效、白巫女手记正文和存档键不变；新回归代码位于 smoke/test 源集，不进入发布 JAR。

## 冗余与边界

属性更新、装备查询与奖励发放存在相似代码；部分早期注释和常量也有整理空间。本次没有据此做跨版本大规模抽象或格式改写，以免把维护性重构混入功能修复。没有发现这些重复结构本身导致本轮运行报错。

本轮结果不能保证任意第三方模组组合、自定义数据包或长期多人服都没有缺陷。可选联动按代码入口检查；未逐个安装所有第三方版本做全组合实测。开发日志中的外网认证请求被环境限制与 Windows 硬件查询警告，和模组逻辑异常分开记录。检查所发现的基线失败记录、修复后日志与成品校验值保存在本地两版的“验证记录/0.43.2”目录。

## 可重复验证

在对应工程中用项目的 `scripts/gradle.ps1` 执行 `build stageMods runServer`，并通过 `-I` 指向 Forge 工程的 `scripts/audit-server.gradle`。该选项只启用开发验证并在结束后关闭测试服务器，不应对正式游戏实例使用。必须检查日志中的 `PROJECT_AUDIT_OK`、`FERIN_LIFECYCLE_OK`、`HARDCORE_OK` 及既有验证通过标记；Minecraft 测试异常后 Gradle 仍可能返回成功，不能只看退出码。

## 最终结果

Forge：122 项单元测试通过；NeoForge：124 项单元测试通过。两版完整构建、服务端回归与客户端图标加载均通过。发布 JAR 与 0.43.1 比对：Forge 的 283 个 assets/data 资源文件、NeoForge 的 309 个资源文件逐字节一致，无新增或删除；测试类未打入发布包。
